# 任务内四智能体认知协同演化

## 系统边界

本系统采用无中心环形拓扑：规划器 P → 规划验证器 Vp → 执行器 W → 执行验证器 Vw → P。每个任务独立初始化，四个角色的状态均为空；没有跨任务状态、模型训练或金标准访问。所有输入均为公开任务描述、工具目录和当前任务中实际观察到的工具结果。`run` 返回的 accepted 只表示验证器在当前证据和预算下接受，不是对客观正确性或穷尽性的证明。

## 状态与证据

第 r 轮的状态记为

\[
M^{(r)}=(M_P^{(r)},M_{Vp}^{(r)},M_W^{(r)},M_{Vw}^{(r)}),\qquad M^{(0)}=(\varnothing,\varnothing,\varnothing,\varnothing).
\]

P 的状态包含已验证锚点、已证伪路径和开放问题；Vp 包含经验护栏和预先登记的验收谓词；W 包含有效工具策略和应避免的模式；Vw 包含已验证断言、已排除噪声及诊断探针。状态均有限长；其中证据性条目必须引用账本中真实存在的观测 ID。ID 存在性只证明引用来源存在，不自动证明语义蕴含；语义判断仍由验证器执行。

宿主对每次实际工具执行记录单调 ID、工具名、规范化参数、成功或错误、结果、轮次和步骤。账本保存原始输出一次；模型仅接收有字符预算的观察窗口及截断元数据。重复失败调用可引用既有记录；对可安全复用的只读调用，复用必须以工具的只读属性为依据，不能假定所有工具无副作用。账本查询由宿主提供，不依赖领域工具支持。无论模型声称什么，模型文本不能创建账本证据。
宿主按工具目录记录 `tool_policy`（`read_only`、`mutating` 或 `unknown`）。计划中必需的只读工具必须有成功观察，或以不同规范化参数得到两次真实终端外部错误/未找到响应；失败不会被当作缺失证据。写入和未知工具不会因计划而被宿主强制调用。达到工具上限或最终轮时，未完成的只读检查作为 `unresolved_issues` 保留，候选只能以 `grounded_round_commit` 收束，不能伪装为 `strict_accept`。

## 轮间校准

P 输出目标、输出契约和有界步骤。Vp 在观察本轮执行数据之前登记可检查的验收谓词，并修复或警示不合法的工具链。W 按照契约、谓词和护栏执行，并提供答案与证据引用。Vw 审查每个候选断言、噪声、输出格式及未解决歧义；若须修订，输出失败模式、竞争假设、区分性检查和决策规则，交回下一轮 P。

预测误差是前轮预期与实际观察的差异，而不是仅凭模型自述产生的奖励。可抽象为

\[
\delta_r = D(\widehat O_r, O_r, A_r),\qquad
M_i^{(r)}=\operatorname{Bound}_i\!\left(\operatorname{Filter}_{L_r}
 (U_i(M_i^{(r-1)},\delta_r))\right),
\]

其中 \(\widehat O_r\) 是计划、验收谓词及预期，\(O_r\) 是宿主账本中的执行观察，\(A_r\) 是 Vw 审核，\(L_r\) 是有效证据 ID 集。`Filter` 删除不存在的引用，并在证据门控开启时拒绝缺少有效观测的经验性写入；`Bound` 限制每类状态容量。开放问题和事先登记的验收谓词属于待检验要求，不应被误认为已验证事实。Vp 根据实际错误、空结果或 Vw 指出的噪声修订其护栏；这是一种任务内、证据约束的模型生成更新，而非参数训练或对预测误差的数值测量。

固定轮次运行时，已接受且具有有效引用的 W 原始答案可作为候选保留。后续候选要替换它，需经 Vw 接受并具有支持变化的账本证据；预算耗尽或未能证伪时保留先前答案。Vw 对格式及噪声提出修订，而不把自写事实当作 W 的答案。工具记录存在性不能单独保证新增事实在语义上成立，因此这一机制依然依赖验证器判断。

## 工程约束

每轮重建提示，不传递多轮原始输出历史；逐条观察及总观察量均设上限并标记截断。各角色使用结构化 JSON；字符串、列表和布尔值的常见变体经规范化处理，无效证据 ID 被过滤，结构错误最多触发一次受预算约束的修复。达到动作上限时允许一次禁用工具的有界综合。模型调用、工具调用、轮次及时间均受独立预算限制；预算耗尽后返回可用的已接受答案或明确的未完成状态。所有状态和账本按任务创建，测试通过脚本化模型和工具离线运行。
